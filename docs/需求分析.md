## 1. 项目背景

企业长期沉淀了两类 PDF 文档，是客户服务、销售和技术支持的核心资料：

1. **产品使用手册** —— 有目录、文字 + 图表、结构清晰，属于"结构化说明性"文档（例如技术参数、故障代码、操作步骤）。
2. **产品宣传手册** —— 海报式、图文混排、版面驱动，信息以视觉排布为主（例如产品卖点、渲染图、特性对比），属于"多模态营销性"文档。

当前两类文档口径不一致、存放分散、版本繁多，缺乏统一入口。用户需要查询**技术参数、故障代码、操作步骤、产品卖点**等信息时，只能人工翻阅 PDF，效率低、易遗漏、难以交叉引用。

## 2. 建设目标

构建一套基于 **C#/.NET** 的 AI 问答系统，对不同文档类型采用**最适配的检索与生成策略**，实现统一、准确、可溯源、多模态的智能问答：

- **准确**：回答有依据，减少幻觉。
- **可溯源**：每个答案可追溯回原始 PDF 中的具体片段 / 表格 / 图片 / 精确坐标。
- **多模态**：不仅能回答文字问题，还能引用或生成「表格、图片、图表」等视觉证据。
- **双策略**：针对两类文档分别路由到最合适的 RAG 链路。
- **可演进**：支持版本管理、多轮对话、反馈闭环、多语言、评估与模型管理，可持续迭代。

## 3. 目标用户与应用场景

| 角色 | 典型问题 | 期望输出 |
| --- | --- | --- |
| 技术服务工程师 | "XX 型号报错 E-203 怎么处理？" | 故障码定义 + 检修步骤 + 对应图文页码/坐标 |
| 售前 / 销售 | "这款产品的核心卖点是什么？相比竞品强在哪？" | 卖点要点 + 宣传页中的原型图 / 特性表 |
| 客户 / 终端用户 | "怎么设置定时功能？支持的电压是多少？" | 操作步骤 + 参数表格 + 手册页码 |
| 研发 / 客服质检 | "哪些型号支持双频？说明书里怎么写的？" | 参数表格 + 原文依据片段 |

## 4. 两类文档画像与策略映射

### 4.1 文档画像对比

| 维度 | 产品使用手册 | 产品宣传手册 |
| --- | --- | --- |
| 结构 | 有目录 / 章节 / 编号 | 版面驱动，无严格目录 |
| 内容载体 | 大量文字 + 少量图表 | 图、文、图标、视觉层次为主 |
| 文本可检索性 | 高（文字成段） | 低（文字零散、多为标语） |
| 信息价值 | 参数、故障码、步骤 | 卖点、外观、特性对比 |
| 语义单元 | 段落 / 章节 / 表格 | 版面区块 / 图文组合 / 视觉元素 |

### 4.2 策略选型

| 文档类型 | 检索策略 | 生成策略 | 核心诉求 |
| --- | --- | --- | --- |
| 产品使用手册 | **混合检索 + 重排序** | 基于文本上下文的精确生成，可溯源到段落、表格与坐标 | 精确、结构化、可溯源 |
| 产品宣传手册 | **多模态 RAG** | 视觉 + 文本联合上下文生成，返回图文证据 | 覆盖视觉信息、卖点还原 |
| 手册复杂关系查询（可选） | **GraphRAG** | 以实体/关系图谱辅助检索，处理跨章节、跨模型的关联型问题 | 关联推理、零散知识串联 |
| 高频重复问答（可选） | **LLM Wiki 缓存层** | 命中即返回缓存答案，避免重复检索与推理 | 降低延迟与成本 |

> **设计原则**：默认不采用"一套通用管线打天下"。系统在入库 / 查询时对文档进行分类路由，使每类文档的检索召回与重排序方式最贴合其物理结构。GraphRAG 与 LLM Wiki 作为**可选项**，不阻塞 MVP，列入阶段三。
>
> **渐进性说明**：GraphRAG 与 LLM Wiki 属"锦上添花"。只有当命中率、成本或复杂关联查询成为明显瓶颈时再引入，避免过度设计。

### 4.3 版本与多语言策略

- **版本策略**：同一文档允许存在多个版本（`document_id` 相同、`version` 不同）。检索**默认命中最新版**，查询时可显式指定版本号；跨版本对比由检索层按版本过滤。
- **多语言策略**：每份文档带 `language` 字段（如 `zh` / `en` / `zh_en`）。支持中英混合检索，便于工业手册双语场景。

## 5. 功能需求

### FR1 文档接入与预处理
- 支持批量导入 PDF，自动判定文档类型（使用手册 / 宣传手册）。
- 对使用手册：抽取目录、按章节切分、保留标题层级、提取表格与本页图表。
- 对宣传手册：做版面分析（区块切分），对图文组合做多模态结构化（配图描述、OCR、版面条块）。
- 保存元数据：`document_id`、`version`、`language`、文件名、页码、目录路径、来源文件。

### FR2 分类路由
- 查询时支持显式指定或自动识别文档类型。
- 一条查询按路由结果进入对应检索链路，可跨类型并行检索并合并。

### FR3 版本与多语言过滤
- 检索默认限定到最新版文档集；支持 `?version=` 参数指定版本。
- 支持按 `language` 过滤；面前后相关问答保留原文档语言。

### FR4 检索与重排序（针对使用手册）
- 混合检索：关键词（BM25 类） + 向量检索（dense embedding）双路召回。
- 重排序（Rerank）模型对召回结果精排，融合语义与关键词得分。
- 支持参数 / 故障码 / 步骤的精确匹配命中与高亮。

### FR5 多模态 RAG（针对宣传手册）
- 以"图文区块"为检索单元，而非仅长文本。
- 检索范围同时覆盖视觉（图像 embedding / 版面描述）与文本。
- 生成时联合注入图片证据、OCR 文本与版块说明。

### FR6 问答与溯源
- 生成答案时给出结构化引用：来源 PDF、页眉页码、章节标题、图片编号。
- 引用需携带 `page_no + bbox（边界框坐标） + chunk_id`，支持前端在原 PDF 中**高亮定位**。

### FR7 多模态输出
- 答案可输出 / 引用文本、表格、图片、图表证据。

### FR8 多轮对话
- 每轮会话带 `conversation_id`，保存历史消息；生成时注入前文以支持追问。
- 首次检索可基于多轮意图做改写 / 澄清。

### FR9 反馈闭环
- 用户可对答案**点赞 / 点踩**；点踩可附原因（如"答案错误 / 来源不相关"）。
- 业务人员可对问题-答案做**人工修正**，优秀修正回写为黄金标注 `QA 对`，用于评测与迭代优化。

### FR10 AI 配置、权限与模型管理
- 模型服务可配置（API Key、BaseUrl、模型名、Embedding / Rerank 模型）。
- **模型版本记录**：持久化 `embedding_model`、`dimension`、`rerank_model`；更换 embedding/rerank 模型时需**重建索引**，系统给出版本对照与重建触发机制。
- 管理员可维护语料库、查看查询日志与审计日志。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 准确性 | 常规问题溯源命中率、答案相关度有明确评测基线（见 §9 评估体系） |
| 性能 | 单条查询端到端延迟（**不含**大模型推理）P95 ≤ 3s；并发 ≥ 20 路；单份约 1000 页 PDF 索引构建 ≤ 30min（以上初值为建议基线，待实测确认） |
| 可追溯 | 每次回答保留检索上下文、引用来源与模型版本，可复查 |
| 可扩展 | 新增 PDF、新增文档类型、替换模型服务均可热插拔 |
| 安全 | 文档级 / 章节级 **ACL 权限控制（RBAC）**；敏感信息脱敏（可配置规则，如内部型号编码、价格、定制信息）；全量审计日志 |
| 兼容 | 运行于工业内网 / 可离线部署的 .NET 服务环境 |
| 可维护 | 支持索引重建、版本回退、模型切换的运维入口 |

## 7. 技术架构（C#/.NET）

### 7.1 分层

```
┌───────────────────────────────────────────────┐
│  表现层  Web / 管理后台 / 运维接口                │
├───────────────────────────────────────────────┤
│  应用服务层  QuestionService、Router、RagOrchestr│
├───────────────────────────────────────────────┤
│  领域层     DocumentClassifier、ManualIndexer、 │
│             BrochureIndexer、HybridRetriever、  │
│             Reranker、MultimodalRetriever、     │
│             GraphRetriever(可选)、LlmWiki(可选)、│
│             CiteBuilder、AnswerService、Feedback│
├───────────────────────────────────────────────┤
│  基础设施层 PDF解析、向量库、向量模型/SDK、LLM/SDK │
└───────────────────────────────────────────────┘
```

### 7.2 技术选型建议

| 模块 | 可选方案（建议优先） |
| --- | --- |
| PDF 解析 / 版面分析 | PdfPig、PdfPig 版面 + OpenXML；或 ASIS PDF 服务（如 PyMuPDF 封装、VLM OCR） |
| 表格 / 图表提取 | 使用手册表格文本化；宣传册走多模态解析 |
| 向量库 / 检索 | Milvus、Qdrant、或 .NET 内置 FAISS 封装（按 `dimension` 分集合） |
| Embedding 模型 | 文本向量 + CLIP 类视觉向量（多模态对齐）；记录 model + dimension |
| 重排序模型 | Cross-Encoder Rerank 或托管 rerank 服务 |
| 图数据库（可选） | NebulaGraph / Neo4j（GraphRAG） |
| LLM 生成 | OpenAI 兼容 / 本地 vLLM / Ollama 服务 |
| 编排框架 | ASP.NET Core（Web API / Minimal API） |
| 对象映射 / 日志 | DI 容器、结构化日志（Serilog） |

> **多模态对齐关键点**：宣传手册中图像需映射为与文本同一向量空间的 embedding，保证"以文搜图、以图搜文、图文混合检索"。
>
> **模型一致性关键点**：所有索引记录其 `embedding_model + dimension`，任一变更触发索引重建，防止跨模型向量不可比。

## 8. 关键数据 / 处理流程

### 8.0 核心数据模型（建议）

- `document(document_id, version, language, type, file, meta)`
- `chunk(chunk_id, document_id, version, language, type, page_no, bbox, section, text/table, image_ref, vector, embedding_model, dimension)`
- `conversation(conversation_id, qa_pairs, feedback)`
- `qa_pair(id, question, answer, citations, sources, rating, corrected_by)`
- `model_registry(embedding_model, dimension, rerank_model, active_flag)`

### 8.1 离线入库管线（Document Ingestion）
1. PDF → 分类（使用手册 / 宣传手册）+ 标记版本与语言
2. 使用手册：章节化切分 → 段落/表格单元 → 生成 embeddings → 写向量库 + 元数据
3. 宣传手册：版面区块化 → 图文组合结构 → 图像向量 + OCR 文本 + 版块描述 → 写向量库
4. 全量写入索引，记录 `语料版本` 与 `embedding_model / dimension`
5. （可选）构建实体关系图谱（GraphRAG） / 预热高频问答缓存（LLM Wiki）

### 8.2 在线问答管线（Online Q&A）
1. 问题预处理（意图/文档类型/版本/语言识别）
2. **路由**：进入使用手册链路 或 宣传手册链路（或并行）
3. 使用手册：混合检索（关键词+向量）→ 重排序 → 上下文组装
4. 宣传手册：多模态检索（视觉+文本）→ 相关图文区块 → 上下文组装
5. 多轮上下文注入（`conversation_id` 关联历史）
6. LLM 生成 answer + citations（来源页码 / 图表 / `page_no+bbox+chunk_id`）
7. 返回结构化结果：`answer、sources、images、confidence、version、language`
8. 记录反馈：点赞 / 点踩 / 修正回写

## 9. 验收标准（建议）

### 9.1 场景通过
- 故障码、参数、操作步骤、产品卖点四个典型场景均有通过用例。
- 抽样 N 条手册类问题：答案**可溯源率 ≥ 95%**，相关度评分达标，引用含坐标可高亮。
- 抽样 M 条宣传类问题：能返回对应图片 / 卖点证据，多模态召回覆盖目标版块。

### 9.2 评估指标（引入 RAGAS）
| 指标 | 说明 | 目标基线（初值待定） |
| --- | --- | --- |
| faithfulness | 答案忠实于检索上下文，不产生幻觉 | ≥ 0.85 |
| answer_relevancy | 答案与问题相关 | ≥ 0.85 |
| context_precision | 检索上下文与问题相关占比 | ≥ 0.80 |

### 9.3 性能与运维
- P95 延迟（不含推理）达标；并发稳定；多版本共存检索正确。
- 新增单份 PDF 可一键入库；索引可重建；模型版本可切换并正确重建。

## 10. 风险与约束

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 宣传手册视觉解析难度 | 版面多样、AI 图表，OCR 与版面切割可能不准 | 用 VLM/版面模型 + 人工标注校准 |
| 多模态向量对齐复杂 | 文本与图像 embedding 需要对齐才能互检 | 使用 CLIP 类模型，统一向量维度 |
| 幻觉与溯源 | 生成可能偏离原文 | 强制引用来源 + 检索置信度阈值 |
| 版本管理引入复杂度 | 多版本易串味、易检索到旧版 | 默认限定最新版 + 版本过滤参数 + 版本审计 |
| 模型切换成本 | 换 embedding/rerank 需全量重建索引 | model_registry 版本对照 + 重建流水线 |
| LLM Wiki 缓存一致性 | 文档更新后缓存可能过期 | 缓存随语料版本失效（hash / 版本号） |
| 工业内网部署 | 大模型/向量模型需离线或内网化 | 选可私有化部署模型 |

## 11. 迭代规划建议

- **阶段一（MVP）**：使用手册混合检索 + 重排序问答 + 版本/语言基础支持，Web API 落地。
- **阶段二**：宣传手册多模态 RAG，版面解析与图文检索；引入多轮对话。
- **阶段三**：统一入口、文档类型自动路由；引入 RAGAS 评估、反馈闭环、模型管理。
- **阶段四（可选增强）**：GraphRAG 复杂关联检索；LLM Wiki 高频缓存层；中英多语言增强。

## 附录 A：术语表

| 术语 | 含义 |
| --- | --- |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| 混合检索 | 关键词检索 + 向量检索 双路融合 |
| 重排序 | 对召回结果二次精排，提升顶部相关性 |
| 多模态 RAG | 检索与生成均融合文本 + 图像两类模态 |
| GraphRAG | 借助实体/关系图谱辅助检索，处理跨章节关联型问题 |

| Embedding | 将文本/图像映射为高维向量用于相似检索 |
| 版面分析 | 识别 PDF 页面中文本块、图片、表格的空间结构 |
| bbox | 页面边界框坐标，用于定位引用做前端高亮 |
| RAGAS | 面向 RAG 的评估指标集（faithfulness / relevancy / context_precision） |
